# Open Questions

## Questions for the product owner

Please answer per question; 'ok' accepts our proposal, which we use as a working assumption until then.

| Q    | Question                                                                    | Our proposal                                                                                                                                                                                                                                                                                            | Answer (date) |
| ---- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| Q-01 | How is a customer identified, given that customer names need not be unique? | Through any of the customer's account IDs: opening a further account for an existing customer and the customer report both take one of the customer's account IDs. Each account belongs to exactly one customer (no joint accounts).                                                                 |               |
| Q-02 | Who assigns the account ID?                                                 | The system, sequentially starting at 00000001. IDs are never reused.                                                                                                                                                                                                                                    |               |
| Q-03 | Who is a "special customer" and how is an overdraft limit granted?          | A bank employee grants a limit per account at any time after opening, with an individual amount (≥ 0, at most two decimals, no upper limit). A "special customer" is a customer with a granted limit, no separate status. Setting a new limit replaces the old one, provided the balance stays within it. |               |
| Q-04 | Which withdrawals are allowed?                                              | Greater than 0, at most two decimals, no upper limit. The balance afterwards must not fall below minus the overdraft limit (0 without limit); otherwise the withdrawal is rejected.                                                                                                                    |               |
| Q-05 | When can an account be closed?                                              | Only when the balance is exactly 0.00.                                                                                                                                                                                                                                                                  |               |
| Q-06 | What applies to a closed account?                                           | It can still be queried and shows status "closed". Deposits, withdrawals, setting an overdraft limit and closing again are rejected. It does not appear in reports, and its ID is never reused.                                                                                                                 |               |
| Q-07 | Which deposit amounts are allowed?                                          | Greater than 0, at most two decimals, no upper limit.                                                                                                                                                                                                                                                   |               |
| Q-08 | Which initial balances are allowed when opening an account?                 | ≥ 0, same format as deposits. Opening without an initial balance means an initial balance of 0.                                                                                                                                                                                                        |               |
| Q-09 | What does the account information show?                                     | Account ID, customer name, balance, overdraft limit and status (open or closed).                                                                                                                                                                                                                       |               |
| Q-10 | What do the two reports contain?                                            | Each open account with account ID, customer name and balance, sorted by account ID, then the total balance as net sum (negative balances subtracted). Output on the command line only. A customer with only closed accounts gets an empty list with total 0.00.                                         |               |
| Q-11 | How are texts and amounts presented on the command line?                    | Texts in English. Amounts without currency symbol, with "." as decimal separator and two decimals, e.g. 1250.50.                                                                                                                                                                                       |               |
| Q-12 | Do all nine functions have the same priority?                               | Yes, all are mandatory.                                                                                                                                                                                                                                                                                 |               |
| Q-13 | Are there quality requirements beyond functionality, e.g. login, response times or logging? | None. The command line is used by one trusted bank employee without login.                                                                                                                                                                                                              |               |

## Team decisions

| Q    | Raw requirement                                 | Point              | Decision                                                                                                                                                         |
| ---- | ----------------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Q-14 | Account ID: 8 digits, not 00000000, unique      | Format             | 8-digit string, leading zeros kept. Input must be exactly 8 digits and not 00000000, otherwise an error is shown.                                                  |
| Q-15 | All functional requirements                     | Rejected operations | Unknown account ID or invalid input: error message, state unchanged.                                                                                            |
| Q-16 | Open account                                    | Customer name      | Must not be empty; leading and trailing spaces are removed.                                                                                                      |
| Q-17 | Deposit money (euros and cents)                 | Calculation        | Amounts are calculated exactly, without rounding errors. Data type: architecture phase.                                                                         |
| Q-18 | No UI required, simple CLI frontend             | Form of the CLI    | Interactive session; data is kept in memory until the program exits. Command syntax: design phase.                                                              |
| Q-19 | No persistency, only interface to database      | Storage            | Database interface with an in-memory implementation for the CLI and a mock for tests. Details: architecture phase.                                               |
